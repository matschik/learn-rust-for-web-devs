Learn Rust for web devs · en français

Apprendre Rust avec un agent IA qui ne code pas à ta place

Un repo-modèle où Claude Code joue le tuteur. Le Rust Book sert de colonne vertébrale, les tests sont rouges au départ, et c'est toi qui écris chaque ligne. L'agent pose les questions, donne des indices et relit.

Parcourir les fiches de cours → Voir le repo

L'idée

Inverser les rôles

Un agent qui écrit le code te fait livrer, pas apprendre. Ici, le dispositif l'empêche de te donner la réponse et le pousse à faire ce qu'un bon prof fait : te faire prédire, te faire lire le compilateur, te faire expliquer ton code.

L'agent comme assistant

« Fais passer ce test. » Il écrit le code, le test passe, tu n'as rien appris sur l'ownership.

L'agent comme tuteur

« Que devient title après l'appel ? » Tu réponds, tu corriges, et tu comprends pourquoi.

Le dispositif

Six pièces, toutes dans le repo

CLAUDE.md

Le contrat pédagogique

Les règles non négociables du tuteur :

  • ne jamais écrire la solution ;
  • des indices en 3 paliers ;
  • un pont avec TS pour chaque concept ;
  • prédire avant de compiler ;
  • le borrow checker expliqué par les permissions R/W/O.
scripts/ + .claude/settings.json

Des hooks, pas des promesses

Une règle écrite peut se contourner, un hook non. L'un bloque toute édition de modules/*/src/ par l'agent. L'autre lance clippy après chaque édition de Rust.

.claude/commands/

Le rituel de séance

/next, /hint, /explain-error, /review, /quiz. Chaque commande encode un geste de prof. Par exemple, /review te demande d'abord d'expliquer ton code.

modules/*/*/

Des tests rouges comme boucle de feedback

Un crate par exercice, avec une fiche de cours puis une fiche pratique. Certains exercices ne compilent pas au départ : le message de rustc fait partie du cours.

PROGRESS.md

Une mémoire entre les séances

L'agent y note ce que tu as validé, tes indices et tes erreurs récurrentes. Au début de la séance suivante, il te repose les concepts fragiles : c'est du rappel espacé.

projects/taskr/

Un fil rouge en TODO(human)

Une API de tâches qui grandit à chaque module, jusqu'à Axum et Postgres. L'agent pose l'échafaudage, les parties intéressantes te reviennent.

Une séance de 30 minutes

Cours, pratique, relecture

  1. /next : quelques questions de rappel, puis la fiche de cours. Elle donne les sections du Rust Book à lire, leurs quiz, l'équivalent TS et un diagramme.
  2. Tu prédis ce que va dire le compilateur, puis tu lances cargo test.
  3. Tu es bloqué ? /hint donne d'abord une question, puis le concept, puis un exemple sur un autre cas.
  4. Les tests sont verts ? /review : tu expliques ton code, puis l'agent le relit comme un dev Rust senior.
  5. Le dashboard local te garde concentré sur l'exercice en cours.

Le parcours

Le Rust Book, chapitre par chapitre, jusqu'au backend

Le parcours suit la version Brown du Rust Book, avec ses quiz et son modèle de permissions. Les modules 7 et 8 sortent du livre pour construire une vraie API.

En orange : les modules disponibles. Les autres arrivent au fil de l'eau.

Démarrer

Trois commandes

Tu as besoin de rustup, de Claude Code, de Node 22 ou plus récent et de jq.

git clone https://github.com/matschik/learn-rust-for-web-devs.git
cd learn-rust-for-web-devs
claude        # puis /next

Adapter à toi

Le repo sert surtout d'inspiration. Forke-le et décris-toi dans un CLAUDE.local.md : prénom, stack, préférences.

Tu peux aussi réécrire la section « L'apprenant » de CLAUDE.md pour un autre profil, un dev Python ou Go par exemple. Le pont avec TS devient alors un pont avec ton langage.

La recette marche pour n'importe quel sujet : un contrat dans CLAUDE.md, des hooks qui le garantissent, des tests rouges et une mémoire.

Fait avec Claude Code, à partir du Rust Book (Brown). Code et fiches sur GitHub.
